# Вручную

### Статический IPv4 без DHCP (Debian / Astra Linux / Ubuntu)
```bash
sudo bash scripts/configure_network.sh
```
Мастер показывает все интерфейсы и их состояние, запрашивает адаптер, IPv4,
префикс/маску, gateway, DNS и метрику маршрута. `-` означает отсутствие gateway
или DNS. Настройки сохраняются через NetworkManager, Netplan либо ifupdown.
Нужны `ip`, `python3`, `flock` и установленный сетевой менеджер; для Netplan — `python3-yaml`.
Скрипт не скачивает пакеты и не настраивает SSID, VLAN, bridge или bond.
Неоднозначные конфигурации и пользовательские ifupdown hooks требуют ручной настройки.

**Запускайте с локальной/IPMI-консоли: изменение адреса может оборвать SSH.**
Резервные копии и инструкции `RESTORE.txt` сохраняются в
`/var/backups/configure-network.*`. Netplan использует `try` с таймаутом 120 секунд
и может затронуть всю сеть; после отмены проверьте откат и восстановите файлы из копии.
В ifupdown без resolvconf изменяется глобальный `/etc/resolv.conf`; управляемый
симлинк скрипт не перезаписывает. Файлы Netplan, генерируемые cloud-init, могут быть
перезаписаны им при следующем запуске — проверьте настройки cloud-init отдельно.

# Бекап docker app, положить в папку с docker-compose.yml
```bash
bash backup-docker.sh
```

# Восстановление docker app из бекапа, положить в папку с docker-compose.yml
```bash
bash restore-docker.sh
```

Оба скрипта показывают меню с выбором томов, bind mounts, образов и конфигов.
Если установлен `whiptail`, используйте стрелки, пробел и Tab. Без него
номера через пробел переключают флажки, `a` выбирает доступные пункты, `n`
снимает выбор, `s` продолжает, `q` отменяет операцию.

Backup сначала предлагает дополнительные контейнеры, которых нет в выбранном
Compose-проекте. Docker не хранит универсальную связь «родитель — потомок»:
выберите нужные контейнеры явно. По умолчанию они выключены. Можно продолжить
без дополнительных контейнеров. В следующем меню появятся их реальные тома,
bind mounts и образы. Общие ресурсы сохраняются один раз. Имена томов остаются
исходными. Для выбранных контейнеров также можно сохранить `docker inspect`.
Эти JSON-файлы могут содержать пароли; каталог нового бэкапа имеет закрытые
права доступа на системах с поддержкой POSIX-прав.

Перед копированием данных остановите управляющий сервис и все контейнеры,
которые используют эти данные. Backup проверяет работающие контейнеры всего
Docker-хоста и отказывается копировать используемые тома или пересекающиеся
bind mounts. Он не останавливает их сам. Не запускайте потребителей данных
до окончания бэкапа. Проверка не обнаруживает запись со стороны процессов
хоста, других Docker-хостов или внешних хранилищ и не заменяет согласованный
снимок приложения/базы данных. Socket, устройства и ссылки не архивируются
как обычные bind mounts. Backup сохраняет локальные образы без `pull`.

Restore показывает доступные архивы и причины недоступности остальных пунктов.
Перед заменой данных он показывает дополнительные контейнеры-потребители и
требует ввода `RESTORE`. Затем он останавливает Compose и этих потребителей,
проверяет отсутствие работающих потребителей повторно и только после этого
заменяет данные. Проверка повторяется перед каждым архивом данных. Она не
блокирует запуск новых контейнеров и не даёт атомарный снимок. На время
восстановления остановите внешние управляющие сервисы и процессы хоста,
которые могут писать эти данные. Контейнеры остаются остановленными.
Восстановление только образов и конфигов не останавливает контейнеры.

`docker inspect` сохраняется только как справка: restore не исполняет JSON и
не создаёт произвольные контейнеры или сети из него. Управляемые контейнеры
должен пересоздать их управляющий сервис (например, AIO mastercontainer),
остальные — оператор по исходной конфигурации. Изменения writable layer
контейнера, tmpfs, внешние secrets и данные вне выбранных mounts в такой бэкап
не входят. Для переноса нужны исходный Compose, его `.env`, служебные файлы
бэкапа и все необходимые выбранные ресурсы; один архив mastercontainer не
содержит данные Nextcloud и PostgreSQL.

# Отключение бесполезного containerd

```bash
nano /etc/docker/daemon.json
```
```
{
    "features": {
        "containerd-snapshotter": false
    }
}
```
```bash
systemctl restart docker
```
